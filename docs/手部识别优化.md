# 小程序手部识别优化

面向微信小程序 VisionKit 手部识别链路的优化记录，目标是压掉「五指张开、机械手某几根还弯着」这类残差，
同时改善抖动手感。改动只落在识别解算层，识别框架本身未替换。

## 一、GitHub / 社区检索结论

| 方向 | 结果 |
| --- | --- |
| 微信小程序 VisionKit 手部开源实现 | **没有可复用的仓库**。GitHub 定向检索基本为空，唯一样板是官方 `wechat-miniprogram/miniprogram-demo` 的 `packageAPI/pages/ar/hand-detect`，本仓库已有代码就是照它写的 |
| MediaPipe 生态（hand landmarker） | 有大量实现，但都是 Web / iOS / Android / Flutter，**不能直接塞进小程序**（小程序没有 TFLite 运行时，VisionKit 是官方唯一可用的手部模型） |
| 可借鉴的做法 | 三条，全部是「解算层的算法技巧」，与模型无关，可直接搬到 VisionKit 输出上 |

可借鉴的三条（本轮已落地前两条）：

1. **用 3D 而不是 2D 顶点算关节角**。
   2D 的失效模式很明确：手掌正对镜头时，手指朝镜头弯曲几乎不改变 2D 投影位置，算法会继续判「伸着」。
   来源：[Control a Robotic Hand With Your Bare Hand](https://www.instructables.com/Control-a-Robotic-Hand-With-Your-Bare-Hand-No-Glov/)
   （webcam 驱动机械手，明确记录了这个坑与 3D 修法）。
2. **角度 + 路径曲率比（curl ratio）双度量**。
   单关节角受掌骨基准与噪声影响，伸直时仍有残差；比值法看整根手指形态，与手的远近/尺度无关。
   来源：[MediaPipe Hands 手指屈曲分析](https://www.kkaneko.jp/ai/labo/handgesture.html)（curl 值定义）、
   [MediaPipe Hands 论文](https://arxiv.org/pdf/2006.10214.pdf)（tracking 优先、必要才重跑 palm detector）。
3. **手掌坐标系归一化**（以手腕为原点 + 手尺寸归一）——社区通用做法，本轮只落地了其中「朝向可用性评分」，
   完整坐标变换留作后续。

## 二、微信官方 3D 能力的准确口径

来源：[人手检测 · 微信开放文档](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/visionkit/hand.html)

- 前置条件：微信 **≥ 8.1.0**（2D 手部检测本身只需基础库 2.28.0）。
- 摄像头实时模式：在 `updateAnchors` 回调里调 `session.update3DMode({ open3d: true })`。
- 开启后 anchor 额外输出：
  - `points3d`：人手 3D 关键点 `(x, y, z)`
  - `camExtArray`：外参 `[R, T \ 0^3, 1]`
  - `camIntArray`：内参，参考 `glm::perspective(fov, w/h, near, far)`
- **3D 点采用 MANO-16 点定义**，与 2D 的 21 点 OpenPose 体系不同。

> 因为 16 点与 21 点的对应关系没有官方逐点映射表，本仓库**不做强行套映射**。
> 只有当 SDK 直接返回 21 点 `points3d` 时才合并 z；否则保持纯 2D 链路，宁可少一个精度档，也不让角度整体错位。

## 三、落地的四处改动

### 1. 3D 开关（`pages/capture/index.js`）

```js
self._3d = self.enable3D();          // session.start 成功后
// enable3D(): typeof s.update3DMode === 'function' 才调，抛错就 return false
```

状态栏会显示 `采集中 · 识别中 · 3D` 以区分当前是否走了 3D。

`mergeDepth()` 负责把 21 点 `points3d` 的 z 合进 2D 点（兼容 `{x,y,z}` 与 `[x,y,z]` 两种结构）。

### 2. 双度量融合（`core/hand.js`）

```js
flex = 0.6 * angleFlex + 0.4 * curlFlex
```

- `angleFlex`：三个关节角的加权平均（拇指 CMC 权重 0.35，其余 0.8），`*1.11` 归一到 100。
- `curlFlex`：`((1 - ratio) / 0.55) * 100`，`ratio = 直线(根→尖) / 折线(根→P1→P2→尖)`。

伸直 `ratio ≈ 0.95~1.0`（≈0），握拳 `ratio ≈ 0.40~0.55`（≈100）。

### 3. 软死区 + 量化（`core/hand.js: sharpenFlex`）

| 区间 | 处理 |
| --- | --- |
| `flex ≤ 8` | 归 0 |
| `8 < flex < 92` | 线性拉伸到 0–100 |
| `flex ≥ 92` | 归 100 |
| 之后 | 按 5% 步进取整 |

目的：张开真的输出 0（舵机不再「以为还弯着」），阈值附近不再来回微动。UI 读数与推给机械手的是同一份值。

### 4. 置信度门槛（`pages/capture/index.js`）

`anchor.confidence < 0.4` → 该帧按「没识别到手」，交给 `PresenceGate` 走宽限期，不产生角度。

## 四、验证

### 方法

合成 21 点数据集直接跑 `core/hand.js`，不依赖真机；同时跑既有回归 `miniprogram/test/verify.js`。

### 结果

| 场景 | 期望 | 实测 |
| --- | --- | --- |
| 五指完全伸直 | 全 0 | 死区后 五指全 0（原始 4.9 / 2.7 / 0 / 2.8 / 5.3） |
| 食指弯曲 90° | 明显 > 0 | 45 |
| 手指朝镜头弯（2D 投影几乎不变） | 3D 应显著高于 2D | 2D 判 21 → 3D 判 43 |
| 手掌朝向评分（张开手） | 接近 1 | 0.81 |
| 既有回归 `test/verify.js` | 不破坏 | **60/60 通过** |

### 复现脚本

```js
var H = require('.../miniprogram/core/hand.js');

// 构造一组 21 点（单位：归一化坐标），例如五指完全伸直
var OPEN = [ /* 见下方要点：四指自掌指关节竖直向上，拇指向右上 */ ];

function sharp(set) {
  var a = H.computeFingerAngles(set);
  H.sharpenFlex(a);
  return H.FINGER_ORDER.map(function (n) { return a[n].flex; });
}
```

要点：
- 伸直用例要让「腕 → 掌指关节 → 近端关节」近似共线，否则本来就会算出残差；
- 3D 对照片例只需把 `pip / dip / tip` 的 `z` 逐级减小（朝镜头），`x/y` 保持几乎不变。

## 五、兼容性与降级

| 情况 | 行为 |
| --- | --- |
| 微信 < 8.1.0 / 基础库无 `update3DMode` | 静默 2D，功能不缺失，精度档少一档 |
| 基础库 < 2.28.0 | 与原来一致：`createVKSession` 直接报错并给出 errno 文案 |
| SDK 只给 16 点 `points3d` | 不合并 z，保持 2D（避免映射错位） |
| `confidence` 字段缺失 | 视为 1.0，不误杀 |

## 六、未做与可选后续

- **网页端未同步**：`app.js` 里的 `computeFingerAngles()` 是独立实现，本轮只改小程序。需要两端一致时把本文件算法搬过去。
- **掌面坐标系变换**：以手腕为原点、掌法线为 z 轴的完整坐标变换，能进一步改善「手侧转」时的角度稳定性；需要基于 3D 点才有意义。
- **角度计算隔帧执行**：当前渲染与解算同频；若真机上 3D 模式掉帧，可把解算降到每 2 帧一次（渲染仍每帧）。
- **`palmPlaneScore` 提示**：已实现但尚未接到 UI。手掌越正对镜头、2D 角度越不可靠，可据此提示「把手侧过来」。
