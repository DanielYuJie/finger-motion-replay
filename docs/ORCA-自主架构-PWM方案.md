# ORCA 自主路线：PWM 平替舵机新架构

决策（2026-11）：不走 HLS/Dynamixel 总线舵机，用 **¥25 级 PWM 舵机**重建执行层，
重新模拟并设计架构。本文是这条自主路线的设计文档。

**目标舵机**（用户提供的参数表）：

| 项 | 值 |
|---|---|
| 控制 | **PWM 500–2500 µs**（三线，无总线） |
| 电压 | **4.8–7.4 V**（推荐用 7.4 V = 2S，拿最大扭矩） |
| 尺寸 | **40 × 20 × 40 mm**（含耳 54.5 mm），重 **55 g** |
| 扭矩 | 堵转 19 KG@6V / **23 KG ≈ 2.26 N·m @7.4V** |
| 速度 | 0.16 s/60° @6V / **0.14 s/60° @7.4V** |
| 角度 | 180° / 270° 可选 |
| 反馈 | **无**（位置/电流都读不回来） |

---

## 1. 可行性结论（模拟结果，脚本 `orca-link/pwm_arch_analysis.py`）

| 维度 | 结论 | 依据 |
|---|---|---|
| **电机行程** | ✅ **180° 覆盖全部 17 关节** | 最大需求 66.2°（thumb_mcp，传动比 0.53 假设），余量 ≥24° |
| **扭矩** | ✅ 不弱于设计基准 | 电机堵转 2.26 N·m = **HLS3915（1.39）的 1.6 倍**；论文 10.5 kg 抓握是在 HLS 上做到的 |
| **速度** | ✅ 余量 10.5× | 关节侧 809°/s vs 实测手势峰值 77°/s |
| **量化精度** | ✅ 不是短板 | PCA9685 12bit → 关节侧 ≈0.85°/步；舵机死区 0.5–1° 才是主导 |
| **重量** | ⚠️ **+544 g** | 17 × 55 g = 935 g（XC330 方案 391 g）→ 前臂必须重新设计并加大 |
| **反馈** | ⚠️ **全部丢失** | 无位置回读 → 开环；无电流回读 → 无法做硬限位自动标定 |

**关键假设（标 [假设]，必须在真件上实测）：**

- 传动比 = 关节滑轮半径 / 线轴缠绕半径 ≈ **4.5 / 8.5 = 0.53**（线轴 OD 21 mm 实测；
  关节滑轮半径 4.5 mm 是 FDM 手指关节典型值，未实测）。分析扫了 0.40/0.53/0.60 三档，
  结论对三档都成立（0.60 时最大需求 75°，仍 < 90°）。
- 扭矩的精确值同样依赖这两个半径——**拿到实体后第一件事就是量它们**。

## 2. 硬件架构

```
                7.4 V (2S 锂电 / 稳压电源)
                        │
        ┌───────────────┼────────────────┐
        ▼               ▼                ▼
   ┌─────────┐    ┌───────────┐    ┌──────────┐
   │ 主控     │    │ PCA9685   │    │ PCA9685  │
   │ (PC/RPi)│──I2C│ #1 (0-15) │    │ #2 (1 路)│
   └─────────┘    └─────┬─────┘    └────┬─────┘
                        │ 16 × PWM      │ 1 × PWM
                        ▼               ▼
                 ┌───────────────────────────┐
                 │  17 × PWM 舵机（16 指 + 1 腕）│
                 │  每个舵机: V+/GND/SIG 三线    │
                 └───────────────────────────┘
```

| 部件 | 选型 | 说明 |
|---|---|---|
| 舵机 | 17 × 180° 版 | 270° 也行但用不上（需求 ≤75°）；选 180° 拿更高分辨率 |
| PWM 驱动 | **2 × PCA9685**（16 路 I2C） | 每路 12-bit；改振荡频率可到 ~1.2 µs/步 |
| 主控 | 现有 PC 即可 | I2C 经 USB-I2C 桥或树莓派 |
| 电源 | **7.4 V**（2S 锂电）或 6 V | 7.4 V 时堵转 2.26 N·m；17 舵机**同时堵转** ≈ 17×1.2A ≈ **20 A**——电源要按此留量，或靠限流/程序约束 |
| 保险 | 必须（板上无） | 无电流反馈，过载只能靠保险丝 |

**前臂布局 [估算]**：16 颗手指舵机按"输出轴指向手指、20 mm 厚度并排"的排法，
需要约 **160 × 80 × 40 mm** 的箱体（两排 8 颗），再加 1 颗手腕舵机。
现有 ORCA 前臂是 88 × 122 × 91 mm——**新前臂形状完全不同，必须重新建模**，
不是改腔位能解决的。

## 3. 软件架构

**保留（已验证）**：

```
MediaPipe 关键点 → orca_teleop 重定向器 → 17 关节角（度）
```

**替换（新写）**：orca_core 的总线电机层 → **PWM 舵机驱动**：

```
17 关节角(度) → [ratio 0.53] → 17 电机角(度)
             → [映射] → duty = 1500 ± 电机角 × 11.11 µs（500–2500 µs / 180°）
             → PCA9685 → 舵机
```

**丢失的能力与替代：**

| 能力 | 总线版 | PWM 版 |
|---|---|---|
| 位置回读 | ✅ 闭环 | ❌ 开环（舵机内部电位器闭环，但控制器看不见） |
| 电流回读 | ✅ | ❌ |
| 硬限位自动标定 | ✅ `calibrate.py` | ❌ → **手工标定** |
| 单线 17 轴 | ✅ 总线菊花链 | ❌ 17 根信号线 + I2C |
| 过载保护 | ✅ 电流环 | ⚠️ 保险丝 + 程序限幅 |

软件落点：`orca_bridge.py` 增加 `--sink pwm`，复用 `orca_hand_map.py` 的关节映射
（那里的 `joint_to_motor` 换算 + 关节 ROM 校验可以直接用）。

## 4. 标定策略（无反馈版）

总线版的 `calibrate.py` 靠"驱到硬限位 + 读堵转电流"自动定极限。PWM 版没有电流，
改为**手工标定**，一次到位：

1. 断电状态下把每个关节手动摆到**最小 ROM 角**，记录此时需要的 duty（手感）
2. 同理标**最大 ROM 角**
3. 两点线性拟合 duty ↔ 关节角（每个关节 2 个标定点，共 34 个点）
4. 中位 = 两极限中点；把结果存进 `pwm_calibration.yaml`
5. **张力**仍用官方棘轮手法（纯机械，不依赖电流），"只拧到有张力感"
6. 首次通电前：**限幅只给 ±30°**，逐步放开，防止标定错误导致手指撞限位

> ⚠️ 开环的固有风险：堵转（腱绳卡死、异物）时舵机会持续输出最大电流直到保险丝断。
> 第一次运行必须小步、低 duty 增量，手放在断电开关上。

## 6. 风险清单（按严重度）

1. **舵机死区与重复精度未知**——规格表没标；开环下这直接决定重现精度。**先买 1 个实测。**
2. **传动比假设（0.53）未验证**——影响行程与扭矩两个结论。拿到线轴/手指件先量半径。
3. **7.4 V 下 17 颗同时堵转 ≈ 20 A**——电源与保险丝必须按此设计。
4. **无过载检测**——堵转烧机风险；程序限幅 + 保险丝兜底。
5. **前臂重新建模**——工作量大头；Blender 网格布尔可行但低模塔身要重画，不如直接参数化重建。
